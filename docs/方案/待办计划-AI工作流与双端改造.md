## 1. 已锁定的决策（计划依据）

### 1.1 目标分三层

| 层 | 是什么 | 例子 |
|---|---|---|
| 日常目标 | 重复性习惯打卡（已有） | 早起、健身、阅读 |
| 小目标 | 一次性成果、需对方验收（已有） | 做一条 AI 小短片、复习某科目 |
| **大目标** | 长期方向，**不能手动打卡**，只能靠绑定的小目标推进（新增） | 找到一份 Agent 开发工程师的工作 |

「目标」栏目多一个大目标入口。大目标有进度条，进度由 AI 分析后写入，另保留 `done/total` 客观计数供核对。

### 1.2 计划链怎么放

- AI 排出的整串小目标**一次性全存好**，没轮到的标「未启动」：不进统计、不进对方「我们」页、不出现在首页。
- 首页只露当前该做的 1–2 个，放在「目标」页 + 首页一块「当前小目标」卡片里，**不塞进日常打卡的今日待办**（那栏目只装早起/健身那类）。
- 前面的延期 → 后面日期整体往后挪；提前完成 → 提前露面。
- **大目标详情页**是整条路线的查看 / 编辑 / 重排入口：能看全路线（含未启动的）、能手改（改日期、改内容、增删、调顺序）、能和 zoowy 讨论后重新规划。Web 和 Android 都要有。
- 手改优先：手改过的日期/内容，zoowy 重排时默认不动，除非用户明说「一起重排」。
- 重排只碰「未启动」的：已进行中 / 待验收 / 已达成的小目标锁死。
- 手改与 AI 重排走**同一套链路**（候选 → 确认 → 写库 → `plan_versions` 快照 → `ai_calls` 记账），不搞两套写入路径。

### 1.3 AI 的权力边界

- AI 只判**进度、画像、计划释放**，**不判打卡真伪、不碰验收通过/驳回、不改积分**。判定权仍在对方手里（延续需求文档 1.4「人只负责验收和兑现」）。
- 需求文档第 15 节原写「AI 判图 / 自动防作弊不做」，本轮不推翻该条——AI 不接管防作弊。

### 1.4 AI 底座（A-2）

- **产品后端自己调大模型 API**，不依赖开发会话里的 agent 手动跑（23:30 定时、推送、双端查看都要求服务端常驻可自动触发）。
- 供应商：**阿里百炼**，走 OpenAI 兼容模式；`app/src/ai.js` 统一适配，换模型只改 `.env`（`AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL`，默认 `qwen-plus`，实现时核对当前可用模型名）。
- **密钥只放服务器 `.env`，不进 git、不下发到 Web/Android**。⚠️ 曾在对话里明文出现过一枚 key，**必须重新生成**后再配置。
- 输出强制结构化 JSON + 落库前校验，解析失败**不写库、不伪造**；`ai_calls` 表记账。

### 1.5 agent 工作流（不是单次 API 调用）

- 不要「调 API 分析 → 再调后端覆盖」的裸链路，要完整的 agent 工作流：**AI 先判断要不要重写，不用重写就整轮跳过**（不调模型、不写库）。
- 拓扑：**一个 zoowy 网关 + 4 个专业工作流**，不搞多个独立 agent（两人自用、单 Node 进程，多 agent 会割裂会话、抢画像读写、成本翻倍）。「专业」体现在每个工作流有自己的提示词、工具白名单、输出 schema。

| 工作流 | 触发 | 说明 |
|---|---|---|
| `plan` 规划 | 大目标页按钮 | 含「先把信息问够」前置阶段，够了才出候选计划 |
| `progress` 进度 | 小目标完成 | 判断要不要动 → 写进度 + 画像补丁 |
| `daily` 日报 | 每晚 23:30 | 两人各一份，写 `diaries` |
| `chat` 常驻问答 | 「我」页 zoowy | 带用户信息的知识库问答 + 保留工具调用能力 |

> 「访谈」不是独立环节：它只是 `plan` 工作流里「信息不够就一次问一个、先给建议答案，问够了才出候选」那一步。

### 1.6 zoowy 双入口分工

| 入口 | 定位 | 怎么干活 |
|---|---|---|
| **「我」页常驻 zoowy** | 带用户信息的**知识库问答聊天助手** | 拿画像/目标/打卡/日记/使用时长当上下文回答问题；照样能调接口写东西，白名单与确认规则不变 |
| **大目标页按钮** | 只干一件事：给这个大目标排小目标 | 创建表单里「让 zoowy 帮忙拆」+ 详情页「重新规划」；点开两条路：①「我先说说想法」②「按已有信息直接来」，**两条路都要先自检信息够不够** |

「知识库」不引向量库——两人数据量很小，直接把该用户的结构化数据拼进上下文即可。两处入口进**同一个 zoowy 会话**，快捷入口带该大目标上下文，不是空聊。

### 1.7 画像 / 日报 / 通知

- **个人画像**：每用户一份，分块存（`basic` / `resume` / `skills` / `goal_progress` / `important`…），含简历、能力、各大目标进度记录、重要信息。每次分析都带上它，**分析也会更新它**。
- 更新规则：不是全文重写，而是**该改的改、该留的留、该删的删**。每轮先 diff，无实质变化就跳过；有变化才输出块级 `add / update / delete` 补丁，必须带 `reason + evidence`，其余块原样保留。优先级：**用户在对话里的最新明确表述 > 用户手改值 > AI 推断值**。删除最严：只标失效、不物理删。每次 apply 前存 `profile_versions` 快照，可看历史、可回滚。
- **用户日记 = AI 日报**：每晚 23:30 按目标完成/未完成 + 画像生成，存库并让用户看到；有重要信息顺带更新画像。放「我」页，**支持查看并修改**（`ai_original` + `user_edited` 两栏，展示用改后版；次日生成新日报不回改昨日）。
- 原需求里的「每日反思总结」**不单独立项**，并入日报的 `user_edited`（自己补一段即反思）。
- **通知形态**：选 A 轻量档 —— WorkManager 15 分钟周期拉取 + `POST_NOTIFICATIONS`，**不申请省电白名单、不挂前台服务、不常驻**；日报额外发 Android 通知栏，Web 是「我」页站内红点。接受 Doze 下可能延迟几十分钟。权限被拒降级成站内红点。
- **同一个 Worker 顺带补报当日手机使用时长**（有使用情况访问权才做），补上 `usage_daily` 历史日期的数据缺口。

### 1.8 安全、确认与设置（G-1）

- **工具白名单按工作流最小授权**：`plan` 只有列目标/建小目标/改计划日期；`progress` 只有读目标/写进度/画像补丁；`daily` 只有读 + 写日记/画像补丁；`chat` 保留调用能力但同一白名单。**绝不给**验收通过/驳回、删目标、改积分、改昵称口令、改任何对方数据。工具层复用现有路由的业务校验（owner / partnerOf），`userId` 由服务端会话注入，AI 不能指定。
- 确认粒度：**勾候选计划 = 一次确认；删除/覆盖已有内容再确认一次**。
- 每用户两个设置：`skipConfirm`（默认关，开了＝每次都不弹确认直接改）、`reportChanges`（默认开＝每次改完都告诉用户，关了＝不汇报直接改）。
- 两条硬边界：① 这两个开关**只能调确认与汇报，不能调工具白名单**；② **不汇报 ≠ 不留痕**，`profile_versions` 与 `ai_calls` 照常写，随时能在「我」页翻到 AI 改过什么。免授权省的是弹窗，不是决策——候选计划仍要用户勾选。
- loop 上限：单次工作流最多 6 轮工具调用、总超时 60s，超了中断并记失败原因；写工具带 `idempotency_key` 防重复建目标、防日报重跑两份。
- 会话存服务端（`zoowy_sessions` / `zoowy_messages`），Web 和 Android 拉同一份，聊天记录不落端上。

### 1.9 可见性分层（C）— 宗旨落点

- **对方全可见**（延续 P2「可见即可信」、现在「我们」页已在看的）：大目标 + 进度条、小目标与计划日期、打卡、积分、验收、手机使用时长。
- **默认仅自己可见**：个人画像全文、AI 日报全文、zoowy 聊天记录。
- 但可**主动分享**：把某一天的日报、或画像里的某几块分享给对方，对方在「我们」页看到摘要；未分享时不摆空壳。
- 一句话：监督落在「做了什么」，不落在「想了什么」。

## 2. 现状与范围

**已有，不用重做**：两人账号与登录、`PATCH /api/me` 改昵称、目标 CRUD / 打卡 / 积分 / 验收 / 愿望单 / 周视图、「我们」页（对方目标、今日打卡、待我验收、并排对比）、`usage_daily` 表与三个时长接口、两端时长对比卡、验证通过/驳回接口与按钮、每日 03:00 自动快照的定时器模式。

**新增**：大目标层、个人画像、AI 日报、zoowy 与 agent 网关、计划链与逐步释放、7 天时长图、待审核详情与接口冒烟脚本、通知栏、可见性分层、按用户的设置。

**技术栈**：Web = Express + 原生 JS（无构建）+ PostgreSQL；Android = Kotlin / Jetpack Compose 单 Activity、手写 `Api.kt` 打同一后端；云端 = 腾讯云 CVM + Docker Compose，公网 IP 明文 HTTP，**只能打 debug 包**。

**已知文件**：现有 `settings` 表是全局 key-value（只存积分系数），`getPoints` 全局读，Web/Android 的「设置」区两人共享一份 → 新增 `user_settings` 按用户存，不动现有积分系数。
