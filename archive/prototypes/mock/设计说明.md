# 原版颜色的三个具体问题，以及像素风格怎么留

## 一、原来的颜色和排版问题

不是「像素不好看」，是**颜色和排版没有替像素服务**。逐条拆：

### 1. 颜色太多层，等于没有主色

原型里同时有：羊皮纸底 `#FAF3E3`、次级底 `#F3E9D2`、卡片 `#FFFDF6`、草绿、深绿、浅绿、蜂蜜橙、深橙、浅橙、红、深红、浅红、蓝、浅蓝、金。

13 个语义色，但界面上一屏能同时出现 8 个。结果：

- 绿色同时表示「主行动 / 已完成 / 选中 / 积分」，含义被稀释
- 橙色同时表示「连续 / 提醒 / 待办 / 愿望单余额」，读不出重点
- 用户学不会「这个颜色意味着什么」

**改法**：主色只留一个（绿），状态色只留两个（暖橙=要注意的，玫红=撤销/危险）。其余全部是中性色。

### 2. 对比度不够，像素字糊在一起

- 正文用 12px 像素字，中文笔画密度高，100% 缩放下已经发虚
- `#7D6C56` 这类弱化字放在 `#FAF3E3` 上，对比只有 3.4:1，低于 4.5
- 像素字的笔画是 1px 方块，字越小，抗锯齿越容易把它抹成一团

**改法**：像素字只用在 **14px 以上** 的标题和 **数字**；正文换系统字体 14px；弱化字统一 `#8C8378` 以上。

### 3. 排版靠「框」撑，不靠留白

- 卡片、列表、按钮、弹层用同一套 2px 描边 + 硬投影
- 一屏 40 处阴影，层级全被拉平，眼睛找不到落点
- 内边距统一 12px，卡片之间也是 12px，组内组外一样宽，结构读不出来

**改法**：只有**一个**元素用重装饰（当前主行动），其余靠对齐和留白分组。

---

## 二、像素风格保留在哪

我的判断：**像素不能当皮肤，要当语法**。它应该承担三件具体的事：

### 1. 像素格 = 打卡数据

这是像素最合理的用法。7 天格子、月历、年度足迹，本来就是格子，用像素方块表达状态，既贴合数据形态，又有辨识度。

### 2. 像素数字 = 积分和统计

`1,318`、`+65`、`86%` 这类数字用像素等宽字体，一眼能和正文区分，自带「游戏数值」的感觉，而且不影响阅读。

### 3. 像素描边 = 只给主行动

打卡按钮、主任务卡用 2px 深描边 + 硬投影，按下去位移 2px。全页只留这几处「实体感」。

### 明确不做的

- 正文不用像素字
- 图标不全部改像素（保留 emoji，反而更有亲和力）
- 不整屏深色，不在每个卡片上加描边

### 保留的比例

| 元素 | 处理 |
|---|---|
| 标题 | 黑体 700，不像素 |
| 数字 / 积分 / 日期 | 像素等宽 |
| 正文 / 列表 | 系统无衬线 14px |
| 打卡格 / 月历 | 像素方块 |
| 主按钮 | 2px 描边 + 2px 下压 |
| 普通卡片 | 1px 细边 + 柔和阴影 |

这套配比的结果就是新 demo 的样子：**远看是普通现代 App，近看每一处数据都是像素格**。
