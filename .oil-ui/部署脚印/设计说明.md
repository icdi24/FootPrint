# 脚印 · V0.1 设计说明

## 任务
把《需求文档.md》的 V0.1 最小闭环部署成可运行的移动优先 Web 应用：两人账号登录、日常目标、打卡+积分流水、商品愿望单兑换、今日待办、基础统计、SQLite+每日快照。UI 模仿 `UI示例/` 三张参考图（男朋友奖惩清单类打卡 App）。

## 品类与用户
- 品类：两人互督打卡积分小工具（伴侣/搭档之间的私人产品），移动端浏览器使用。
- 用户来首屏看什么：今天要打哪些卡、还差多少、自己攒了多少分；主动作是「打卡」。
- 标杆（= 用户给的参考图）：浅粉底 + 白圆角卡 + 绿色对勾 + 多彩 emoji 图标 + 周网格打卡表 + 橙色选中日 + 绿色悬浮 +。同类产品把「完成」做成整个界面最亮的动作，弱化其他一切。

## 方向卡（选定：粉彩手账）
- 一句话：像一本两人共用的粉色手账，每天最重要的事是「打上勾」。
- 感觉：轻、暖、可信，不严肃不游戏化，像真实的纸面打卡表。
- 骨架：底部 5 Tab（今天/目标/愿望单/我们/我的）；首页=问候 + 积分横幅 + 今日待办卡片流，每张卡一个硕大的绿色「完成」；目标页=周网格打卡表（直接继承参考图构图）。
- 字体：系统中文无衬线（PingFang SC / Microsoft YaHei），数字用等宽变体；标题 17-20px，正文 14-15px。
- 色彩：底色 #FAE7EA 粉、卡片纯白、主绿 #4FA46C（对勾/按钮/FAB）、强调橙 #F2994A（选中日/火苗/连击）、警示红 #D96C6C（驳回/偏高），文字 #3B3435 / #8C7F81。
- 图标：目标用 emoji（直接继承参考图的「彩色图标」气质，这是用户指定的参考风格，非模型默认）；UI 动作图标用自绘 1.5px 圆头线条 SVG 一套。
- 控件语法：16-20px 大圆角、白色卡片 + 极浅粉描边、轻投影、按下缩至 0.96；主按钮绿色实心圆角，危险动作用红。
- 素材：无摄影图，emoji + 色块构成全部主视觉。

### 差异检验（与标杆并排）
与参考 App 的共性：粉底白卡、绿勾网格、emoji 图标、周视图。差异（来自本产品理由）：① 参考图是单一列表，我们信息更多（积分/愿望单/双人），所以用底部 Tab 而非单页；② 积分是核心资产，首页顶部给积分横幅（参考图没有）；③ 「对方可见」是支柱 P2，独立「我们」Tab 放监督与对比；④ 里程碑奖励用 🔥 与橙色表达连击，这是本产品独有的时间激励层。

## 三处基本动效
1. 主操作反馈：打卡成功 → 对勾描画弹出 + 得分数字滚动 + 卡片翻转为完成态，重复点击不重播。
2. 状态切换来路：底部 Tab 切换用滑动指示条 + 页面淡入上移（240ms）；周网格点击格子即时填充。
3. 首次进入出场：首页卡片按序浮入（间隔 60ms，总长 <600ms）；里程碑弹窗从顶部滑入 3s 自动消失。
- 手感参照「回弹」（刚度 300/阻尼 8）：小物件过冲 10-15%，整页不过冲。
- 全部尊重 prefers-reduced-motion。

## 设备与验收重点
- 视口 360–480px 宽（截图用 390×844）；打卡路径 = 首页「完成」→ 弹层「打卡」，共 2 次点击、<10 秒。
- 验收重点：周网格对齐与参考图神似度、首页一屏内看到待办与积分、文字对比度、打卡成功反馈、长目标名截断有完整入口。
